# 图章生成器 · 双端实现与同步约定

本项目是对 `图章.exe` 的**源代码级重构**，产出两个彼此独立、可单独运行的应用程序：

| 文件 | 运行方式 | 渲染引擎 |
|---|---|---|
| `图章生成器.html` | 双击用浏览器打开（离线可用，无外部依赖） | Canvas 2D 矢量渲染 |
| `图章生成器.py` | `python 图章生成器.py`（需 Pillow） | Pillow 位图 + 3× 超采样 |

两者**不是**互相嵌套、也不是同一份代码编译两次，而是各自完整的独立实现，靠下面这份约定保持一致。

---

## 一、参数模型（JSON 契约）

两个程序导出的 `图章参数.json` 结构完全相同，可以直接互相载入。

```

design.linkScale   bool            改外框尺寸时按比例缩放内容，默认 true（见「算法约定」第 10 条）
frame.visible      bool             外框开关
frame.shape        enum              circle | ellipse | rect | diamond | triangle
frame.w / .h       number   mm      宽度 / 高度（圆章用 w 作直径）
frame.stroke       number   mm      线宽，0 = 不描边
frame.color        string   #rrggbb
inner.*            ——               与外框同名同义，内框
axis.visible       bool             中心线 / 中心框
axis.w / .h        number   mm      高度 ≤ 线宽时退化为一条横线
axis.stroke        number   mm
axis.dx / .dy      number   mm
axis.color         string

symbol.kind        enum              star5 | image
symbol.radius      number   mm      外接圆半径
symbol.ratio       number           五角星内径比，默认 0.38197（= sin18°/sin54°）
symbol.dx / .dy    number   mm
symbol.color       string
symbol.img         string           自定义图符：Web 版存 dataURL，桌面版存文件路径
texts[i].visible   bool             文本 1/2/3 各自独立
texts[i].content   string
texts[i].font      string            字体名，默认「宋体」
texts[i].fontCustom string           自定义字体名/路径，非空时优先
texts[i].bold      bool             加粗
texts[i].size      number   mm      字号（字高）
texts[i].stretch   number           横向缩放，1 = 原始比例
texts[i].spacing   number   mm      字距（平排、弧排都用）
texts[i].mode      enum              ring | arc | flat
texts[i].radius    number   mm      半径（字中心到圆心），环排与弧排共用
texts[i].startAngle number  °       起始角度；弧排下是「弧的中心角」
```

三个字段，含义完全相同——每个绘制对象可以各自使用不同的纹理与浓淡。

## 二、算法约定（两版必须一致）

1. **单位**：内部一律毫米。像素换算 `px = mm / 25.4 × dpi`。预览与导出用同一个换算，只是 dpi 不同。
   - **画布尺寸只由外框决定**：`画布 = 外框宽/高 + 留白×2`（原程序说明：「图形的最终输出大小按外线设置」）。
     内框不参与——否则内框比外框大、或内框线宽为 0 时，画布会被撑大却没有任何内容。
   - **圆章只有一个尺寸**：宽度即直径。界面上圆章时的「高度」控件**与直径联动**——拖宽度或拖高度都是改直径，
     两个控件始终显示同一个值，画布也始终是正方形（高度不参与绘制）。
2. **角度原点**：`0° = 12 点方向`，顺时针为正。
   - 环排字符坐标：`x = cx + R·sin(a)`，`y = cy − R·cos(a)`
   - 字符旋转角 = `a`（字头朝外）；`inward = true` 时 = `a + 180°`
   - 每字角度：`a_i = startAngle + i × stepAngle`；`autoStep` 时 `stepAngle = 360 / 字数`
3. **五角星**：10 个顶点，外点/内点交替，从 −90° 起每 36° 一个；内径比 `r = R · sin18° / sin54° ≈ 0.38197R`。
4. **平排**：逐字按实际字形步进（`字宽 × stretch + spacing`），整体以 `cx + dx` 居中对齐。
5. **弧排（arc）**：以 `startAngle` 为**弧的中心**，沿半径 `R` 把整串字铺开。
   - 每字在弧长方向的位置 `s_i = −L/2 + 前面各字宽度累计 + 本字半宽`，`L` 为总弧长
   - `arcSpan > 0` 时 `L = arcSpan × π/180 × R`，字宽按 `L / Σ字宽` 等比压/拉；`arcSpan = 0` 时 `L = Σ字宽 + 间距`
   - 方向：`dir = sign(cos a₀ + sin a₀)`——让字符顺序始终符合屏幕上的「向右 / 向下」阅读方向，
     所以底部文字不需要手动把字序反过来
   - 角度 `a_i = a₀ + dir × s_i / R`（弧度换度），坐标与环排同式
   - 旋转角：`inward = false` → `a_i`；`inward = true` → `a_i + 180°`（此时字顶朝圆心）
6. **绕中心排布预设**（面板按钮，只改排法不改其他）：
   | 按钮 | mode | startAngle | inward | 效果 |
   |---|---|---|---|---|
   | 顶部 | arc | 0° | false | 顶部弧形，字头朝外 |
   | 底部 | arc | 180° | true | 底部弧形，**正立，字顶朝圆心** |
   | 左侧 | arc | 270° | false | 左侧竖向，自上而下 |
   | 右侧 | arc | 90° | false | 右侧竖向，自上而下 |
   预设同时把 `dx`、`dy` 清 0、`arcSpan` 置 0——因为弧排的位置由「半径 + 角度」决定，
   叠加平排偏移会把文字推出画布。
7. **单字定位（关键，容易做错）**：每个字符先画到独立小图层再旋转/摆放，图层必须按**字格**建，不能按墨迹建：
   - 水平：图层宽 = 该字的 **advance（前进宽度）**，墨迹保持它在字格内的原始位置。
     若改成「按墨迹宽度居中」，`，。：` 这类偏在一侧的字会整体平移（实测偏移 1.84mm），
     且相邻字间距忽大忽小。
   - 垂直：图层高 = `ascent + descent` **行框**，墨迹保持行框内的原始纵向位置。
     若改成「按墨迹高度居中」，`一` 这类扁字会浮到行中间，同一行的字不在一条基线上。
   - 弧排压缩（见上条 `k`）：`k<1` 时**字形与间距一起压**，否则间距压了、字形没压，字会互相压叠；
     `k>1` 时只拉开间距，字形保持原宽（横向拉伸会变形）。
8. **抗锯齿**：Web 版靠 Canvas 原生抗锯齿；桌面版以超采样（预览 2×、导出 3×）渲染后缩小。
   缩小时 `fast=True` 用 crop + box 平均（快 4~5 倍），`fast=False` 用 LANCZOS（笔画边缘略锐，用于导出）。
   两者墨迹包围盒完全一致。
9. **导出**：透明底 PNG，并写入 DPI 元数据；Web 版另支持导出 SVG（矢量，可再编辑）。
   SVG 的文字字宽用离屏 Canvas 实测（与预览同一套度量），图符用 `preserveAspectRatio="none"` 强制铺满正方框——
   与 Canvas `drawImage` 的拉伸行为一致，避免"导出的 SVG 和预览不一样"。
10. **改外框尺寸 = 整体缩放内容**（默认开启，`design.linkScale`；这是让「改直径」看起来像"章变大变小"的关键）：
    - 触发点：`frame.w` / `frame.h` 的改动（滑块与数字框都走同一个入口）。
    - 比例 `k = 新尺寸 / 旧尺寸`。按 k 缩放：外框/内框/中心线的**线宽**、内框 `w/h`、中心线 `w/h/dx/dy`、
      图符 `radius/dx/dy`、文本 `size/radius/spacing/dx/dy`、以及所有对象的 `textureScale`。
      线宽必须跟着缩——只缩几何不缩线宽，10mm 的小章上 1.2mm 的圆环会粗得像甜甜圈。
    - **不缩放**：外框 `w/h`（它是驱动量本身）、留白（纸边距）、DPI。
    - 缩放后要把**所有控件的显示值刷新一遍**（`refreshCtlValues()` / `refresh_all()`），
      否则面板里内框、线宽、字号还写着旧数字。
    - 连续拖动是逐次相乘，首尾之比正好等于总比例；缩放值保留 6 位小数，
      实测 40↔24 来回 50 次后所有参数逐字段复原（`same: true`）。
    - 椭圆/方/菱/三角的宽、高各自独立触发，用各自维度的比例；圆章两个控件指向同一个直径。
    - 关掉这个开关就回到「全是绝对值、互不联动」的老行为（改外框后需要自己调内框/图符/文字）。
    - 入口：Web `setFrameSize()` + `scaleContent()`，桌面 `_set_frame_size()` + `scale_content()`。

## 二·补 纹理（画笔纹理）

原程序支持「画笔纹理」：把 PNG 纹理当作笔刷，让墨迹出现斑驳/颗粒感。两版都实现了，且机制相同：

1. **不是**给图形填图，而是**调制墨迹覆盖度**——纹理的 alpha 决定哪里"上得上墨"，哪里"漏白"。颜色仍由对象自身的 `color` 决定。
2. 实现步骤（两版一致）：
   ```
   把该对象单独画到一张透明图层
   → 用纹理平铺后作为遮罩，与该图层 alpha 相乘
   → 合成回主图
   ```
   Web 版用 `globalCompositeOperation='destination-in'` + `createPattern`；
   桌面版用 `ImageChops.multiply(图层α, 纹理α)` + `alpha_composite`。
3. **内置纹理 4 种**，由程序生成、不依赖任何图片文件，两端**逐像素完全相同**
   （LCG 种子 `20241117`，乘数 `1103515245`，增量 `12345`，取 `(s>>16)&0xFF`）：

   | id | 名称 | 生成规则 |
   |---|---|---|
   | `noise` | 斑驳 | `α = 255 − v³ × 220` |
   | `fine` | 细颗粒 | `α = 255 − v⁵ × 180` |
   | `stripe` | 斜纹 | `(x+y) % 14 < 10 ? 255 : 60` |
   | `dot` | 网点 | `(x%9−4)² + (y%9−4)² ≤ 6 ? 255 : 120` |

   已用脚本比对两端采样值，四个纹理全部一致。
4. **外部纹理**：
   - 桌面版启动时扫描程序目录下的 `纹理/` 文件夹（首次运行会自动创建），文件名即纹理名，与原程序行为一致；
   - Web 版无法读目录，用「纹理库 → 选择 PNG…」在本次会话里载入（可多选）。
5. `textureScale` 是"一块纹理盖多少毫米"，`textureOpacity` 是浓淡；两者都按对象独立设置。

## 三、改一处就要同步另一处

修改功能时请按此清单逐项核对：

| 改动 | Web 版位置 | 桌面版位置 |
|---|---|---|
| 默认参数 | `defaultParams()` / `defaultText()` | `default_params()` / `default_text()` |
| 控件清单 | `SECTIONS`（由 `buildPanel` 装配） | `SECTIONS`（由 `_section` 装配） |
| 渲染顺序 | `render()` | `render_image()` |
| 环排/弧排/平排定位 | `renderText()` | `_draw_text()` |
| 绕中心预设 | `ARC_PRESETS` / `applyPreset()` | `ARC_PRESETS` / `apply_preset()` |
| 五星顶点 | `starVertices()` | `star_vertices()` |
| 外框路径 | `framePath()` | `draw_frame()` |
| 对象分图层+纹理遮罩 | `paintObj()` | `render_image()` 内的 `paint()` |
| 纹理生成 | `makeTexCanvas()` | `make_tex_image()` |
| 纹理平铺/相乘 | Canvas `createPattern` + `destination-in` | `apply_texture()` |
| 单位换算 | `designBox()` | `design_box()` |
| 预览画布尺寸 | `fit()`——尺寸类参数（直径/高度/留白/内框开关）一改，`paint()` 会比对 `designBox()` 决定是否重排画布 | `redraw()`——画布固定，图按 ppm 居中贴图 |
| 改外框尺寸（等比缩放内容） | `setFrameSize()` / `scaleContent()` | `_set_frame_size()` / `scale_content()` |
| 字体表 | `FONT_LIST` | `FONT_FILES` |

命名尽量一一对应，方便对照阅读。

**面板不要随便重建**：Web 版 `buildPanel()` 一调用，所有分组都会回到「只有文本 1 展开」的初始状态，
正在调的「文本 2/3」会自己合上，还丢滚动位置和焦点。所以：

- 只改了几个字段（绕中心排布预设）→ 用 `refreshCtlValues()` 就地刷新控件，**不重建**；
- 确实要重建（载入外部纹理）→ 走 `rebuildKeepScroll()`，它保留滚动位置，`buildPanel()` 内部还会按分组标题
  记忆并还原展开状态。

## 四、字体与「默认字体」

- **默认字体是宋体**，两版都把 `DEFAULT_FONT = '宋体'` 写死在默认参数里；载入旧参数时若字体缺失也回落到宋体。
- 内置可切换：宋体 / 新宋体 / 黑体 / 楷体 / 仿宋 / 微软雅黑 / 等线 / 华文中宋 / 华文行楷 / 华文隶书 / 隶书。
- **每个文本对象各自有字体下拉框和「加粗」开关**（文本 1/2/3 互不影响），另有「自定义字体」输入框可填系统里任何字体名或字体文件路径。
- 加粗策略：
  - Web 版用 `font-weight: 700`；
  - 桌面版优先使用真粗体文件（微软雅黑 → `msyhbd.ttc`、等线 → `Dengb.ttf`），没有粗体文件的字体用描边模拟（`stroke_width ≈ 0.02em`）。

## 五、已知的实现差异（不影响视觉一致）

1. **自定义图符**：Web 版把图片内联为 dataURL 存进 JSON；桌面版存本地文件路径。跨端载入时该字段会失效，重新选图即可。
2. **文字度量**：Canvas 与 Pillow 的字形 advance 有细微差别（< 0.3%），环排/弧排时整体弧度可能有零点几度的差异；`arcSpan > 0` 的弧排因为按字宽等比压缩，两端每个字宽的细微差别会累积成 1~2% 的字宽差异。
   垂直方向：桌面版按 `ascent+descent` 行框居中，Canvas 的 `textBaseline=middle` 按 em 方块中点居中，同一段文字两版会差 0.1~0.4mm（实测 3.4mm 字号差 0.34mm）。水平中心、总宽、墨迹范围基本一致。
3. **SVG 导出**：只有 Web 版有；桌面版只导出 PNG（Pillow 写 SVG 需要额外的文字转路径步骤）。
4. **外部纹理**：只在各自一侧"存在"才算有效——Web 版是本次会话载入的，桌面版是 `纹理/` 目录里的同名文件。跨端载入参数时，纹理 id 会保留，但若对面没有同名文件则回退为"无纹理"（内置 4 种纹理不受影响）。

## 六、性能（2026-11-17 实测，300 DPI 661×661）

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 桌面版 · 预览（ss=2） | 49 ms | **24 ms** |
| 桌面版 · 导出（ss=3） | 103 ms | **87 ms** |
| 桌面版 · 导出 + 4 层纹理 | 153 ms | **87 ms** |

做法（结果与优化前逐像素一致，已用基准图验证 `最大差=0`）：

1. **超采样缩小**：整数倍用 `crop + reduce`（box 平均）代替 LANCZOS，单次 50ms → 11ms。
   预览走快速路径，导出仍用 LANCZOS 保证笔画锐度。
2. **纹理只处理墨迹包围盒**：原先每层都新建整图图层并全图合成；改为画完后取 `getbbox()`，
   只对这块做遮罩与 `alpha_composite(dest=...)`。平铺起点按图层在画布中的偏移取模，纹理相位与全图对齐。
3. **纹理缩放缓存**：同一 `(纹理, 缩放尺寸)` 只缩一次。
4. **字符图层内边距**：`0.18em` → `0.03em + 描边宽度`，旋转计算量按面积下降约 40%（不再需要那么大留白）。
5. **桌面版重绘节流**：原来是「取消 + 70ms 防抖」，拖滑块时每帧都被取消、全程不刷新；改为 45ms 节流。
6. **Web 版 `paint()` 用 rAF 合并**：同一帧内多次 input 只重绘一次；纹理重复图案（pattern）缓存，不再每次 `createPattern`。

上一轮还可挖但没做的：文字图层也是先建整图再画，理论上可预估包围盒只建小块（多对象带纹理时约再省 25ms），
但需要给所有绘制函数加坐标平移，收益递减、出错风险高，暂不做。

## 七、使用

**Web 版**：双击 `图章生成器.html` → 左侧调参 → 顶部「导出 PNG / 导出 SVG」。

**桌面版**：
```
pip install pillow customtkinter    # Pillow 负责渲染，customtkinter 负责界面样式
python 图章生成器.py
```

第一次运行桌面版时会自动在程序目录下创建 `纹理/` 文件夹，把 PNG 丢进去、重启即可在下拉框里选到。

**桌面版界面**：用 **customtkinter** 搭的（圆角、扁平、DPI 清晰），配色沿用网页版那套
（`#f5f5f3` 底 / `#ffffff` 面板 / `#b32b1c` 主色 / `#e3e2de` 细线）。左侧分组可折叠（点标题栏），
默认展开状态与网页版一致（画布与输出 / 外框 / 文本 1 展开，其余收起）。

改界面时注意几条约定：

- 控件到参数的映射仍走 `self.vars`：`("num", StringVar, fd)` / `("bool", CBool)` / `("sel"|"font"|"text"|"color"|"tex", var, ...)` / `("seg", {值: 按钮})`；
  滑块额外存 `vars[path+"#slider"]`，色块存 `vars[path+"#swatch"]`。`refresh_all()` 靠这些回写显示值。
- `CBool` 是 CTkCheckBox 的 `get()/set()` 包装，因为 `refresh_all` 只认这两个方法。
- 滑块 `set()` 必须放在 `pack()` **之后**：画布还没尺寸时 set 会把圆点画在最左端（踩过）。
- CTkEntry 没暴露 `justify`，右对齐靠 `entry._entry.configure(justify="right")`。
- 分组三角用 `tk.Canvas` 自绘（`▸/▾` 在微软雅黑下缺字形会显示成横线）。
- **面板滚轮速度**由 `WHEEL_EXTRA` 控制（默认 2 → 每格 60px）。CTk 在 Windows 上把滚轮写死成
  `int(delta/6)` 个单位、且 `yscrollincrement=1`，即每格只走 20px，手感发黏；
  而它的滚轮是实例方法 + `bind_all` 注册的，直接改倍数无效、调 `yscrollincrement` 又会让滚轮失控。
  所以 `_boost_wheel()` 追加一个同序列绑定，在 CTk 滚完之后补滚 `WHEEL_EXTRA` 倍。
  觉得还慢/太快改这一个常量即可（0 = 回到 CTk 原生速度）。

- `示例_300dpi.png` —— 默认参数（无纹理），两版输出一致性的对照样张。
- `示例_纹理.png` —— 外框与文字用「斑驳」、五角星用「斜纹」、内圈用「网点」，纹理效果样张。
- `示例_底部环绕.png` —— 底部文字用「绕中心排布 → 底部」：正立、字顶朝圆心、沿弧铺开。

**让底部文字绕中心排（字顶朝圆心）**：选中文本 2 → 「绕中心排布」点「底部」。
想让弧更平就加大「半径」，想更弯或更集中就调「弧长跨度」（0 表示按字宽自然排）。
